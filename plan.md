## 1 Докеризація NestJS додатку для production середовища

Для production-середовища потрібно написати звичайний Dockerfile для створення образу додатку, який можна потім задеплоїти на AWS.

В якості хостингу для Docker образу можна використати [DockerhHub](https://hub.docker.com) чи [AWS ECR](https://aws.amazon.com/ecr/).

## 2 Розробка AWS-інфраструктури production-додатку

Для виконання даного завдання варто використати будь-який інструмент для побудови візуальних діаграм. Це може бути [draw.io](https://app.diagrams.net/) чи [Cloudcraft](https://www.cloudcraft.co/).

У ньому варто представити інфраструктуру, яка буде використовуватися у тестовому завданні.
В інфраструктурі потрібно використати Elastic Container Service (ECS), оскільки, він призначений для запуску Docker-образів.
Також, на діаграмі варто вказати додаткові елементи, на зразок роутера, ролей, серверних інстансів та інше.

За натхненням можна звернутися [сюди](https://warren2lynch.medium.com/aws-architecture-diagram-with-2019-new-icons-over-50-examples-d401a76c6d5c).

## 3 Автоматичне розгортання інфраструктури за допомогою Terraform / CloudFormation / інші

Наступним кроком буде опис інфраструктури за допомогою коду (Terraform).

Програмно повинні створюватися усі ресурси AWS (мабуть, за вийнятком доменного імені та бази даних). VPC(Route table, Subnets, Internet Gateway, etc.), ECS (Service, Task, ALB, etc.), Cloudwatch (Log configuration), Certificate Manager (for HTTPS traffic).

Базу даних можна захостити на [MongoDB Cloud](https://www.mongodb.com/cloud). Тут повинна бути безкоштовна версія.
Доменне ім'я, можна придбати на сервісі [Namecheap](https://www.namecheap.com/).

Врезультаті, повинен вийти код, який автоматично розгортає всю інфраструктуру та дозволяє деплоїти туди зміни.

## 4 Налаштування деплою додатку на AWS за допомогою GitLab/GitHub pipelines

Для тестування роботи із CI/CD будемо використовувати GitLab або GitHub pipelines (для open-source проектів вони безкоштовні).

Потрібно налаштувати правила, які при кожній зміні в гілці master будуть виконувати тестування додатку (`npm run test`), білд нового образу та деплой його на сервер.

Як уже згадувалося раніше, для хостингу образів можна використовувати [DockerhHub](https://hub.docker.com) або [AWS ECR](https://aws.amazon.com/ecr/). Репозиторій із образом повинен бути приватним.

Якщо тести при проходженні падають, то деплой не повинен відбуватися.
